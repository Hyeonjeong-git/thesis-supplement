《等级标准》 단어 9,456개를 16개 대분류 아래 47개 소분류로 분류하고 각 단어에 한국어 뜻을 부여한 카테고리 어휘 테이블과, 47개 소분류에 대응하는 144종의 의뢰 시나리오를 담은 의뢰 템플릿 테이블을 구축하였다. 게임의 라운드 생성은 이 두 테이블의 동적 조합으로 이루어진다.

자료 01

카테고리 어휘 테이블 (categorized_cihui)

의뢰 목표 태그에 제시되는 한국어 의미를 미리 구축·검증된 이 테이블에서 직접 불러오도록 설계함으로써, AI 기반 실시간 번역에 의존하지 않고 일관된 번역 품질을 보장한다.

자료 02

의뢰 템플릿 테이블 (commission_templates)

46개 소분류에 난이도 1·2·3의 의뢰를 1개씩 배분하고 태도·성격 소분류에만 난이도별 2개씩을 배분하여 총 144종을 구성하였다. 이로써 대부분의 소분류가 난이도별로 동등한 수의 의뢰를 갖게 되었다.

전환

설계 전환 기록

부수 분해 방식에서 단어 조합 방식으로

초기 설계에서는 AI가 한자의 부수를 실시간으로 분해하고 학습자가 부수 카드를 조합하여 한자를 완성하는 방식을 시도하였다. 그러나 잘못된 부수 제시, 존재하지 않는 부수 생성, 카드 풀과 정답 불일치 등의 오류가 반복되었다. 프롬프트 강화와 자체 검증 지시로 정확성을 확보하고자 하였으나 한계가 해소되지 않아, 사전 검증된 어휘 데이터베이스 기반의 단어 조합 방식으로 게임 메카닉스를 전환하였다.

자료 14

전환에 이른 세 차례의 수정 프롬프트

이 경험은 프롬프트 엔지니어링만으로는 도메인 특화 지식의 정확성을 보장할 수 없으며, AI 생성과 검증된 데이터베이스를 결합하는 접근이 필요하다는 점을 보여준다.
자료에 관하여

이 페이지는 학위논문 제3장 3.2에서 다룬 한자 연금술의 개발 기록 가운데, 지면에서 생략한 프롬프트 입력 기록과 개발 과정의 주요 화면을 수록한 것이다. 화면은 개발 당시의 기록이며 현재의 웹앱과 다를 수 있다.

프롬프트 표와 입력 내용은 실제 입력 기록이므로 문구를 사후에 수정하지 않았다. 표 안의 색상 견본은 열람 편의를 위해 화면에서만 덧붙인 것으로, 원문에는 없다.

[부록 표16-1] RISEN 프레임워크 기반 팩트 체커 S1 프롬프트 설계

RISEN 요소 · 팩트 체커 S1 적용
Role(역할)중국어 교육 게이미피케이션 웹앱 개발자. AI 생성 영상(무음)과 Azure TTS 내레이션을 동시 재생한 뒤, 텍스트 문제의 정오를 판단하고 녹음으로 설명하는 팩트 체크 게임을 구현한다
Instructions(지시)Supabase에서 5개 테이블의 데이터를 로드하여 게임을 구현한다. 영상 무음 루프 재생, Azure TTS 내레이션 동시 재생, 다시 듣기, 텍스트 문제 표시, 체크와 녹음 분기, ASR Edge Function 호출(최종 결과만 사용, 중간 결과 누적 금지), Claude API 판정 Edge Function 호출(동음자 면제), 100점 만점 채점, 에피소드별 리더보드, 진행 저장 및 복원, 반응형 레이아웃, excellent 판정 시 모범 표현 숨김을 포함한다
Steps(단계)① 첨부 SQL 파일로 5개 테이블 생성 및 데이터 삽입, ② zhaoca-judge Edge Function 생성(Claude API 판정, 동음자 면제 프롬프트 포함), ③ 월드 선택과 에피소드 선택 화면 구현(전 월드 해금), ④ 영상 재생(무음 루프)과 Azure TTS 내레이션 동시 재생 화면 구현(다시 듣기 포함), ⑤ 텍스트 문제 표시와 체크 및 녹음 분기, ⑥ ASR 변환(최종 결과만 수신)과 Claude API 판정 호출, ⑦ 피드백 표시(excellent 시 모범 표현 숨김)와 결과 화면 구현, ⑧ 반응형 레이아웃
End goal(최종 목표)3월드 3에피소드의 팩트 체크 게임. 영상과 내레이션 동시 재생, 체크와 녹음 분기, 이중 판정 구조, ASR 동음자 안내 문구, 리더보드, 진행 저장을 갖춘 듣기·읽기·말하기 통합 학습형 게임
Narrowing(범위 한정)① 영상은 사전 생성하여 Cloudinary URL로 제공한다. ② 내레이션은 Azure TTS 캐싱 Edge Function으로 생성한다. ③ 체크 시 API 호출 없이 프론트엔드에서 판정한다. ④ ASR 결과는 녹음 완료 후 최종 텍스트 1회만 수신하며, 중간 결과를 누적하지 않는다. ⑤ Claude API 판정에서 동음자는 오류로 지적하지 않는다. ⑥ 기존 게임 코드는 일체 수정하지 않는다

[부록 표16-2] 팩트 체커 1단계 프롬프트 핵심 구현 지시

구현 영역 · 핵심 지시 내용
SQL 테이블 생성zhaoca_worlds, zhaoca_episodes, zhaoca_questions, zhaoca_progress, zhaoca_leaderboard의 5개 테이블. RLS 설정: 콘텐츠 3테이블은 전체 읽기, 진행 기록과 리더보드는 사용자별 읽기·쓰기
시드 데이터월드 3행(견습/탐사/수석 기자), 에피소드 3행(video_url, narration_zh, question_count), 문제 8행(question_type narration/visual, is_correct, error_type, expected_answer_zh)
영상 재생<video loop muted>로 Cloudinary MP4 무음 루프 재생. Azure TTS 캐싱 Edge Function 호출로 narration_zh 텍스트를 음성 변환하여 영상과 동시 재생(1회). 다시 듣기 버튼으로 내레이션 재재생. 내레이션 1회 재생 완료 후 문제 풀기 시작 버튼 활성화
문제 풀기 화면문제 유형 아이콘(🎧 narration, 👁 visual)과 라벨, 문제 텍스트(Noto Sans SC), ✅ 맞음 버튼(녹색), ✅ 틀림 버튼(빨간). 상단에 영상 축소 루프 유지
이중 판정 구조✅ 체크: 프론트엔드에서 is_correct 매칭(API 호출 없음). 🎤 녹음: 녹음 완료 후 음성 데이터를 ASR Edge Function에 1회 전송하여 최종 텍스트 수신(중간 결과 누적 금지), is_correct=false이면 zhaoca-judge Edge Function 호출
zhaoca-judge Edge Function입력: episode_narration_zh, question_text_zh, expected_answer_zh, error_type, transcribed_text, level_range. Claude API 시스템 프롬프트에 등급별 기대 수준(1~3급 키워드 수준, 4~6급 완전 문장, 7~9급 논리적 설명)과 동음자 면제(他们/她们, 的/地/得 등) 명시. 출력: result(excellent/great/good/poor), score_ratio, feedback_kr, corrections, suggested_text
ASR 동음자 안내ASR 결과 아래 "※ 음성 인식 결과입니다. 동음자(他们/她们 등)는 실제 발화와 다를 수 있습니다."(text-xs text-gray-400 italic)
excellent 처리excellent 판정 시 모범 표현을 숨기고 "훌륭합니다! 모범적인 표현입니다." 메시지로 대체. great/good/poor 시 모범 표현 표시
반응형 레이아웃max-w-lg(512px) mx-auto px-4. 영상 가로 전체 폭 16:9. 모든 버튼 min-h-[44px]. 문제 텍스트 text-lg md:text-xl. 가로 스크롤 금지

[부록 표16-3] RISEN 프레임워크 기반 팩트 체커 S2 프롬프트 설계

RISEN 요소 · 팩트 체커 S2 적용
Role(역할)중국어 교육 게이미피케이션 웹앱 개발자. S1에서 구현한 팩트 체크 게임에 보도 신뢰도 게이지, 시간 제한, 콤보 보너스, 효과음, 배점 자동 분배를 추가하여 퀴즈에서 게임으로 전환한다
Instructions(지시)월드명을 기자 콘셉트로 변경하고, 보도 신뢰도 게이지(0~100%)를 문제 수 기반 자동 배점으로 구현하며, 문제당 시간 제한(30초, 녹음 시 60초)과 콤보 보너스(2연속, 3연속 이상)를 추가하고, 효과음 7종과 게이지 애니메이션을 구현하며, 판정 결과별 오버레이 피드백 문구를 정교화하고, 게임 방법 안내 텍스트를 갱신한다
Steps(단계)① Supabase에서 월드명 UPDATE SQL 실행, ② 보도 신뢰도 게이지 구현(문제 수 기반 자동 배점, 100% cap), ③ 시간 제한 구현(30초와 60초, 시간 초과 처리), ④ 콤보 보너스 구현(화면 중앙 오버레이), ⑤ 효과음 7종 구현, ⑥ 판정 결과별 오버레이 피드백 문구 정교화, ⑦ 게임 방법 안내 텍스트 교체
End goal(최종 목표)보도 신뢰도 게이지와 시간 제한과 콤보 보너스와 효과음을 갖춘 게임성 있는 팩트 체크 게임. 완벽 플레이 시 반드시 100%에 도달하며, 보도 등급이 최종 성과를 표시한다
Narrowing(범위 한정)① 게이지 표시는 최대 100%로 cap한다. ② 콤보와 피드백 오버레이는 화면 중앙 fixed로 표시하여 레이아웃에 영향을 주지 않는다. ③ 배점은 문제 수 기반 자동 분배로 한다. ④ 기존 게임 코드, Edge Function, Supabase 테이블 스키마를 수정하지 않는다

[부록 표16-4] 팩트 체커 2단계 프롬프트 핵심 구현 지시

구현 영역 · 핵심 지시 내용
월드명 변경Supabase UPDATE SQL로 초급/初等 → 견습 기자/实习记者, 중급/中等 → 탐사 기자/调查记者, 고급/高等 → 수석 기자/首席记者. 프론트엔드 하드코딩 부분도 동일하게 수정
보도 신뢰도 게이지0%에서 시작, 상한 100%(Math.min(값, 100)), 하한 0%. 문제 풀기 화면 상단에 가로 프로그레스 바 상시 표시. 라벨 "보도 신뢰도". 증가 시 초록색 transition(0.5초), 감소 시 빨간색 깜빡임(0.3초)
배점 자동 분배문제당 배점 = 100% ÷ 문제 수(마지막 문제에서 나머지 보정). 2문제: 50%+50%, 3문제: 33%+33%+34%. 정답 체크 배점 100%, excellent 100%, great 80%, good 50%, poor 20%, 오판(틀린데 체크) -50%, 오판(맞는데 녹음) -30%, 시간 초과 -50%
시간 제한문제 표시 시 30초 카운트다운. 🎤 녹음 선택 시 60초로 확장. 10초 이하에서 빨간색 깜빡임. 시간 초과 시 배점의 -50% 감점, 오버레이 표시, 다음 문제 이동
콤보 보너스정답(체크+실제 정답, 또는 녹음+실제 오답+excellent/great) 연속 시 2연속 +5%, 3연속 이상 +10%. 오판 또는 poor 시 콤보 리셋
오버레이 피드백화면 중앙 fixed(z-index: 50), 1~1.5초 후 자동 소멸, 레이아웃 영향 없음. 판정 결과별 차등 문구와 색상: excellent "🎉 정답! 완벽한 설명입니다!"(초록), great "✅ 정답! 좋은 설명입니다!"(초록), good "△ 부분 정답"(노란), poor "▽ 지적은 맞지만, 설명이 부정확합니다"(주황), 오판 "❌ 오판!"(빨강), 시간 초과 "⏰ 시간 초과!"(노란)
효과음7종웹 오디오 기반. 정답 "딩!", 오판 "부웅", 콤보 "콤보!", 시간 경고 "틱틱"(10초 이하), 시간 초과 "타임아웃", 녹음 시작 "삐", 게임 클리어 팡파레
보도 등급90%↑ ⭐ 특종 보도, 70%↑ 📰 보도 성공, 50%↑ 📋 보도 통과, 50%↓ ❌ 보도 실패. 결과 화면에 등급별 메시지 표시

[부록 표16-6] 팩트 체커 3단계 프롬프트 핵심 구현 지시

구현 영역 · 핵심 지시 내용
기자 칭호 시스템4단계 칭호: 👑 전설의 기자(3EP 전부 100%), 🏆 에이스 기자(3EP 전부 90%↑), 📰 정규 기자(3EP 전부 50%↑), 📓 수습 기자(1EP 이상 클리어). 월드별 독립 판정, zhaoca_progress의 is_cleared와 score 조회, 프론트엔드 계산(별도 DB 불필요). 월드 선택 화면 타이틀 아래에 현재 칭호 표시, 결과 화면에서 칭호 업그레이드 시 알림

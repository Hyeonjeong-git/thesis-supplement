[부록 표11-1] RISEN 프레임워크 기반 징검다리 점프 S1 프롬프트 설계

RISEN 요소 · 징검다리 점프 S1 적용
Role(역할)중국어 교육 게임 설계자이자 React 웹앱 개발 전문가. Supabase 데이터베이스 설계와 문장 단위 징검다리 UI 구현에 정통한 전문가
Instructions (지시)Supabase에 5개 테이블을 생성하고 7개 CSV(1,195행)를 적재한다. 10구간 여정 맵과 구간 내 게임 플레이의 2화면 웹앱을 구현한다. 학습자가 전문장을 발음하면 시뮬레이션으로 판정하고, 단어 단위 징검돌에 순차 애니메이션으로 반영한다. 3단계 힌트를 단계적 해금으로 제공한다
Steps(단계)① Supabase 5개 테이블 생성 및 7개 CSV 적재, ② 10구간 여정 맵 화면 구현, ③ 게임 플레이 화면 구현(HUD, 문장, 힌트, 징검돌), ④ MediaRecorder 녹음 및 시뮬레이션 판정, ⑤ 징검돌 순차 애니메이션, ⑥ 별점·라이프·콤보·재시도 구현
End goal(최종 목표)10구간 여정 맵과 징검다리 게임의 기본 골격. 시뮬레이션 판정으로 작동하는 프로토타입
Narrowing(범위 한정)① 발음 판정은 시뮬레이션만 구현한다(iFLYTEK ISE 연동은 S2). ② 이미지 에셋은 적용하지 않는다. ③ 기존 게임 코드를 수정하지 않는다
자료 02

[부록 표11-2] 징검다리 점프 1단계 프롬프트 핵심 구현 지시

구현 영역 · 핵심 지시 내용
SQL 테이블 생성stepping_sentences(1,195행)의 학습 데이터 테이블과 section_stats, sentence_stars, sessions, user_badges의 4개 사용자 데이터 테이블을 생성한다. 7개 CSV를 Lovable에 첨부하여 stepping_sentences에 적재한다
여정 맵10구간 카드를 세로로 배치한다. 구간명, 문형 대분류, 문장 수, 별 수집 현황을 표시한다. 어느 구간에서도 자유롭게 진입 가능하다
징검돌 배치문장의 words JSON 배열 길이(3~11개)만큼 징검돌을 수평 배치한다. 각 돌에 해당 단어를 표시한다. 판정 전 회색, 정답 초록(밝아짐), 오답 빨강(흔들림)으로 0.4초 간격 순차 반영한다
시뮬레이션 판정마이크 녹음 완료 후 70% 확률 정답으로 판정한다. words 배열의 각 단어를 랜덤으로 성공/실패 배분한다
3단계 힌트1단계(듣기): TTS 모범 발음 재생. 2단계(병음): pinyin_display 표시. 3단계(뜻): meaning_kr 표시. 단계적 해금(듣기→병음→뜻). 무힌트 성공 시 점수 50% 보너스
별점·라이프★★★ 무힌트 1차 완벽, ★★☆ 1차 완벽, ★☆☆ 재시도 포함 70%+, ☆☆☆ 실패. 라이프 5개, 1차 실패 시 -1, 재시도 시 반값 점수+라이프 추가 미소모

2단계(S2) 프롬프트

RISEN 프롬프트 설계와 Lovable 입력 프롬프트의 핵심 지시

자료 03

[부록 표11-3] RISEN 프레임워크 기반 징검다리 점프 S2 프롬프트 설계

RISEN 요소 · 징검다리 점프 S2 적용
Role(역할)중국어 교육 게임 설계자이자 iFLYTEK ISE 발음 평가 기술 전문가. WebSocket 기반 실시간 API 연동 구조를 설계하고 문장 수준 발음 평가 시스템을 구현할 수 있는 전문가
Instructions (지시)S1의 시뮬레이션 판정을 iFLYTEK ISE read_sentence 실시간 판정으로 교체한다. Edge Function에서 WebSocket 연결, HMAC-SHA256 인증, 음성 분할 전송, XML 파싱을 구현한다. 글자별 판정을 단어 단위로 합산하여 징검돌에 매핑하고, 오류 유형별 심각도 3단계 피드백을 구현한다. 급수별 check_type 동적 조절, 이미지 18장, Azure Neural TTS 캐싱, 오답 노트(DB 영속), 배지 10종을 구현한다
Steps(단계)① Edge Function evaluate-stepping 생성(iFLYTEK ISE WebSocket 연동), ② 글자→단어 징검돌 매핑 및 순차 애니메이션, ③ 오류 유형 피드백 팝업 및 심각도 3단계, ④ 급수별 check_type 동적 조절, ⑤ Azure Neural TTS 캐싱, ⑥ 이미지 18장 적용, ⑦ 여정 맵 리디자인, ⑧ 모바일 레이아웃 최적화, ⑨ DB 저장·오답 노트(DB 영속)·배지 10종
End goal(최종 목표)iFLYTEK ISE read_sentence 기반 실시간 문장 발음 판정, 1,195개 문장의 징검다리 게임 완성판
Narrowing(범위 한정)① 한 징검돌에 속한 글자 중 하나라도 dp_message ≠ 0이면 해당 징검돌은 실패. ② API 지연은 로딩 애니메이션으로 처리. ③ 기존 게임 코드를 수정하지 않는다
자료 04

[부록 표11-4] 징검다리 점프 2단계 프롬프트 핵심 구현 지시

구현 영역 · 핵심 지시 내용
iFLYTEK ISE 연동Edge Function evaluate-stepping을 생성한다. WebSocket으로 wss://ise-api.xfyun.cn/v2/open-ise에 연결하고, HMAC-SHA256 인증, PCM 오디오 1280바이트씩 40ms 간격 분할 전송, XML 응답 파싱(글자별 phone_score, tone_score, dp_message, fluency_score, integrity_score)을 구현한다
글자→단어 징검돌 매핑ISE 글자별 판정을 words 배열 기준으로 단어 단위로 합산한다. 한 징검돌에 속한 글자 중 하나라도 dp_message ≠ 0이면 해당 징검돌은 실패. 0.4초 간격 순차 성공/실패 애니메이션을 구현한다
오류 피드백dp_message 4종(0 정상, 16 누락, 32 대체, 64 추가, 128 되읽기)을 심각도 3단계(경미·보통·심각)로 분류한다. 돌 탭 시 오류 상세 팝업을 표시한다
check_type 동적 조절level 1~2급 easy, 3~5급 common, 6~7~9급 hard로 채점 엄격도를 자동 조절한다
Azure Neural TTS 캐싱성조 클라임의 Edge Function(text-to-speech)을 재사용한다. 힌트 1단계(듣기) 시 모범 발음 재생, base64 캐싱
이미지·UICloudinary 이미지 18장(판다 3 + 징검돌 4 + 배경 1 + 구간 카드 10). 여정 맵 리디자인. 모바일 징검돌 반응형 그리드(8개 이상 단어 시 2행 자동 줄바꿈)
오답 노트(DB 영속)stepping_wrong_notes 테이블 추가. 오답 발생 시 INSERT/UPDATE(최신 시도 유지). 문장+단어별 점수 바+오류 유형+TTS 버튼
자료에 관하여

이 페이지는 학위논문 부록 1 가운데 5.4 문장 발음 게임: 징검다리 점프의 단계별 프롬프트 기록을 옮긴 것이다. 본문에는 이를 하나로 요약한 RISEN 통합 표만 실었다. 부록 1 전체 목록으로 돌아가기

핵심 구현 지시 표는 Lovable에 입력한 프롬프트 가운데 핵심 지시에 해당하는 부분을 정리한 것으로, 프롬프트 전문은 아니다. 제시한 문구는 실제 입력 기록이므로 사후에 수정하지 않았으며, 본문에서 ‘웹앱의 데이터 저장소(Lovable Cloud)’로 표기한 대상이 ‘Supabase’로 나타나는 등 본문 표기와 일치하지 않는 부분이 있다.

자료 01

[부록 표15-1] RISEN 프레임워크 기반 위챗 언더커버 S1 프롬프트 설계

RISEN 요소 · S1 적용
Role(역할)중국어 교육 게이미피케이션 웹앱 개발자. 위챗 스타일 대화 인터페이스에서 NPC 영상 속 중국어 음성을 듣고 텍스트로 응답하는 잠입 대화 게임을 구현한다
Instructions(지시)Supabase에서 6개 테이블의 데이터를 로드하여 게임을 구현한다. NPC 영상 재생, 중국어 텍스트 자유 입력, Claude API Edge Function 판정, 의심 게이지 0~100 관리, NPC 속마음 풀 랜덤 표시, 부적절 판정 시 재시도 1회, 100점 만점 채점 체계, 에피소드별 리더보드, 진행 저장 및 복원, 다시 듣기 기능, 효과음 6종을 포함한다
Steps(단계)① 첨부 SQL 파일로 6개 테이블 생성 및 EP1 데이터 삽입, ② Edge Function(wechat-undercover-judge) 생성, ③ 게임 시작 화면과 월드 선택 화면 구현, ④ 에피소드 선택과 미션 브리핑 화면 구현, ⑤ 위챗 스타일 대화 화면 구현(NPC 영상 재생, 자막 미표시, 자동 턴 전환), ⑥ 학습자 텍스트 입력과 Claude API 판정 호출, ⑦ 의심 게이지 변동과 NPC 속마음 표시, ⑧ 부적절 판정 시 재시도 1회 기회, ⑨ 미션 성공과 실패 분기 처리, ⑩ 결과 화면과 턴별 대화 기록과 리더보드 구현, ⑪ 진행 저장 및 복원 구현, ⑫ 효과음 6종 구현, ⑬ 모바일 반응형 최적화
End goal(최종 목표)3월드 3에피소드의 잠입 대화 게임. AI 영상 재생, 자유 텍스트 입력, Claude API 실시간 판정, 의심 게이지, NPC 속마음, 재시도 기회, 리더보드, 진행 저장, 효과음을 갖춘 듣기와 쓰기 학습형 잠입 게임
Narrowing(범위 한정)① NPC 영상은 사전 생성하여 Cloudinary URL로 제공한다. ② 플레이 중 Claude API 호출은 매 턴 1회이다. ③ NPC 발화 텍스트는 학습자 화면에 표시하지 않는다. ④ 비로그인 사용자도 플레이 가능하되 진행 저장과 리더보드 등록은 로그인 사용자에 한한다. ⑤ 기존 게임 코드는 일체 수정하지 않는다
자료 02

[부록 표15-2] 위챗 언더커버 1단계 프롬프트 핵심 구현 지시

구현 영역 · 핵심 지시 내용
SQL 테이블 생성wechat_worlds(3행), wechat_episodes, wechat_turns, wechat_inner_voices(60행), wechat_progress, wechat_leaderboard의 6개 테이블. inner_voices는 result_type(natural/awkward/inappropriate/no_response) × level_group(beginner/intermediate/advanced) × 5개 = 60행
Edge Functionwechat-undercover-judge: Claude API 시스템 프롬프트로 맥락 적합성, 언어 자연스러움, 의미 전달 3기준 판정. 출력: result, gauge_delta(natural -5~-10, awkward +15~+20, inappropriate +30~+40), feedback_kr. "natural의 범위를 넓게 설정"하는 지침 포함. 빈 입력은 API 호출 없이 no_response(+25) 즉시 반환
NPC 발화 미표시NPC 영상 클립만 재생하고 npc_text_zh 텍스트는 화면에 표시하지 않는다. 듣기 전용 설계. npc_text_zh는 DB에 유지(Claude API 판정에 필요). 결과 화면의 턴별 대화 기록에서만 NPC 발화 텍스트 표시
위챗 대화UI배경 #EDEDED, NPC 말풍선 흰색(좌측), 학습자 말풍선 #95EC69(우측). NPC 프로필 이미지(원형 36px md:44px). 영상 16:9 비율, 대화 영역 65%(md:80%). "🔄 다시 듣기" 버튼 게이지 +5. 전송 버튼 #07C160
자동 턴 전환판정 결과 수신 → 게이지 업데이트(애니메이션) → 속마음 표시 → 2초 대기(setTimeout) → 자동으로 다음 턴 NPC 영상 표시. "다음 턴" 버튼 미사용
부적절 재시도inappropriate 판정 시 같은 턴에서 재시도 1회 허용(총 2회 시도). 재시도에서도 inappropriate이면 다음 턴 자동 전환
게임 중 피드백게임 중(ChatRoom)에서 feedback_kr을 표시하지 않는다. 속마음과 게이지 변동만 표시. feedback_kr은 결과 화면(ResultModal)의 턴별 대화 기록에서만 확인 가능
점수 계산100점 만점. 대화 품질(60점): 턴별 배점 = 60/turn_count, natural ×1.0, awkward ×0.5, inappropriate/no_response ×0. 잔여 게이지(20점): (100 - 최종 게이지)/100 × 20. 소요 시간(20점): 기준 = turn_count × 60초, 초과 시 감점

이 페이지는 학위논문 부록 1 가운데 6.4 맥락 응답 게임: 위챗 언더커버의 단계별 프롬프트 기록을 옮긴 것이다. 본문에는 이를 하나로 요약한 RISEN 통합 표만 실었다. 부록 1 전체 목록으로 돌아가기

핵심 구현 지시 표는 Lovable에 입력한 프롬프트 가운데 핵심 지시에 해당하는 부분을 정리한 것으로, 프롬프트 전문은 아니다. 제시한 문구는 실제 입력 기록이므로 사후에 수정하지 않았으며, 본문에서 ‘웹앱의 데이터 저장소(Lovable Cloud)’로 표기한 대상이 ‘Supabase’로 나타나는 등 본문 표기와 일치하지 않는 부분이 있다.

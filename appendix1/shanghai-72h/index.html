[부록 표8-1] RISEN 프레임워크 기반 상하이 72시간 S1 프롬프트 설계

RISEN 요소 · 상하이 72시간 S1 적용
Role(역할)중국어 교육 시뮬레이션 어드벤처 게임을 구현하는 React/TypeScript 웹앱 개발 전문가. AI 생성 이미지 기반 대화형 게임 메카닉스에 정통하며, 씬 기반 스토리 진행과 선택지 응답 구조, Cloudinary 정적 이미지 호스팅을 활용한 비주얼 노벨형 게임을 설계할 수 있는 전문가
Instructions (지시)Cloudinary에 사전 업로드한 51개 이미지(장면 배경 21장, UI 배경 4장, NPC 상반신 13장, 플레이어 캐릭터 상반신 2장, 오브젝트 11장)의 URL을 ASSET_MAP으로 등록한다. 7개 에피소드 38개 퀴즈 씬, 내레이션 씬(Day 시작·종료 7개), EP 클리어 씬 6개를 scenes.ts에 하드코딩한다. 이름 입력과 캐릭터(남/여) 선택 후 Day 선택 화면에서 3일간의 여행 스토리를 진행한다. NPC의 중국어 질문에 2~3개 선택지 중 정답을 선택하면 다음 씬으로 오답이면 목숨 1개 감소 후 같은 씬에서 재시도하는 구조를 구현한다. 내레이션(내면 독백)은 플레이어 입력 이름({playerName})으로 화자를 표시하며, 중국어·병음·한국어를 동시에 제공한다. 에피소드 완료 시 EP 클리어 화면, Day 완료 시 보상 아이템(키카드·쇼핑백·보딩패스)을 표시한다
Steps(단계)① assets.ts에 ASSET_MAP 51개 이미지 Cloudinary URL 매핑 등록 및 resolveAsset·preloadImage 함수 구현, ② scenes.ts에 타입 정의(Scene, Choice, CharacterPlacement)와 DAY_CONFIG(3일 × 7EP), 상수 정의, ③ 내레이션 씬 7개(Day 시작·종료) 하드코딩, ④ 7EP 38개 퀴즈 씬(NPC 대사·선택지·정오답·배경·캐릭터 매핑) 하드코딩, ⑤ EP 클리어 씬 6개 하드코딩, ⑥ Shanghai72Page.tsx에 게임 흐름 구현(이름 입력 → 캐릭터 선택 → Day 선택 → 씬 진행 → EP/Day 클리어), ⑦ 목숨(하트)·힌트·타이머 시스템 구현, ⑧ 메인 허브 이미지 기반 게임 카드에 상하이 72시간 연결
End goal(최종 목표)3일 7에피소드 38문항의 상하이 여행 시뮬레이션 게임. 51장 AI 이미지와 Cloudinary 호스팅으로 시각적 세계관을 형성하고, NPC 대화와 선택지 응답으로 여행 상황별 중국어 의사소통 표현을 학습하는 시뮬레이션 어드벤처의 기본 골격. 내레이션(내면 독백)이 플레이어 시점의 여행 서사를 제공하며, 게임 플레이 중 AI API 호출은 0회이다
Narrowing(범위 한정)모든 씬 데이터는 scenes.ts에 하드코딩하며 Supabase 데이터베이스를 사용하지 않는다. 이미지는 Cloudinary에 사전 업로드된 정적 파일이다. 난이도 선택 기능은 이 단계에서 미구현이다. 효과음, TTS 음성 재생, 선택지 셔플, 글래스모피즘 UI는 이 단계에서 미적용이다. 게임 플레이 중 AI API 호출은 0회이다. 기존 다른 게임 코드를 수정하지 않는다

[부록 표8-2] 상하이 72시간 1단계 프롬프트 핵심 구현 지시

구현 영역 · 핵심 지시 내용
ASSET_MAP 등록assets.ts에 51개 이미지의 Cloudinary URL을 ID-URL 매핑으로 등록한다. resolveAsset(assetId) 함수는 ASSET_MAP에서 URL을 반환하고, http로 시작하는 값은 그대로 반환하며, 매핑되지 않은 ID는 빈 문자열을 반환한다
씬 데이터 타입Scene 타입: id, episode, title, backgroundAssetId, characterAssetId, npcName, npcDialogue(chinese, pinyin, translation), choices[], mode(quiz/narration), speakerType(npc/player_prompt). Choice 타입: id, text(중국어), pinyin, translation(한국어), nextSceneId, timeCost, isCorrect
퀴즈 씬 구조(예시){ id: "sh72_ep01_s01", episode: 1, backgroundAssetId: "SH-BG-EP01-S02", characterAssetId: "SH-CH-OFFICER-01-BUST", npcName: "입국 심사관", npcDialogue: { chinese: "您好！请问您的护照在哪里？", pinyin: "Nín hǎo! Qǐngwèn nín de hùzhào zài nǎlǐ?", translation: "안녕하세요! 여권이 어디 있습니까?" }, choices: [정답→다음 씬, 오답→같은 씬(timeCost:1)] } — 이 구조로 38개 퀴즈 씬을 작성한다
내레이션 씬 구조mode: "narration", npcName: "{playerName}", characterAssetId: ""(캐릭터 미표시), choices에 "继续" 버튼 1개(isCorrect: true, timeCost: 0). Day 시작 내레이션 예시: { chinese: "终于到上海了！", translation: "드디어 상하이에 도착했어!" }
DAY_CONFIGDay 1: startScene "sh72_day1_intro", objectAssetId "SH-OBJ-HOTEL-KEYCARD-01"(호텔 키카드). Day 2: startScene "sh72_day2_intro", objectAssetId "SH-OBJ-SOUVENIR-BAG-01"(쇼핑백). Day 3: startScene "sh72_day3_intro", objectAssetId "SH-OBJ-AIR-TICKET-01"(보딩패스)
게임 흐름이름 입력 → 캐릭터(남/여) 선택 → Day 선택(3개 카드) → 씬 진행(배경 전체화면 + 캐릭터 우하단 + 대화 패널 하단 + 선택지 버튼) → 정답이면 다음 씬, 오답이면 목숨 -1 후 재시도 → EP 클리어 → Day 클리어(보상 아이템) → 게임 클리어

RISEN 요소 · 상하이 72시간 S2 적용
Role(역할)S1으로 구현된 상하이 72시간 게임의 플레이 UX를 개선하고, 난이도 3단계 선택 UI, 선택지 런타임 셔플, WebAudio API 효과음, TTS 음성 재생 기능, 글래스모피즘 기반 UI 리디자인, 캐릭터 애니메이션 조건 분리를 적용하여 게임을 완성하는 React/TypeScript 웹앱 개발 전문가
Instructions (지시)S1에서 구현한 게임에 다음을 적용한다. (1) 게임 진입 시 난이도 3단계 선택 화면 추가(첫 상하이·상하이 적응 중·상하이 마스터), (2) 선택지 런타임 셔플 적용, (3) 캐릭터 변경 시에만 애니메이션 실행하는 조건 분리, (4) WebAudio API 기반 효과음 7종 코드 내 직접 생성, (5) TTS 음성 재생 기능(NPC 씬 자동 재생, 듣기 버튼), (6) 글래스모피즘 기반 Start/Day Select 화면 리디자인
Steps(단계)① 난이도 3단계 선택 UI 추가, ② 선택지 런타임 셔플 적용(Fisher-Yates), ③ 캐릭터 애니메이션 조건 분리(dialogueAnimKey vs characterAnimKey), ④ WebAudio API 효과음 7종 구현, ⑤ TTS 음성 재생 구현(Web Speech API fallback), ⑥ 글래스모피즘 UI 리디자인(타임라인 Day 카드, 상태 배지)
End goal(최종 목표)난이도 3단계 선택, 선택지 셔플, 효과음 7종, TTS 음성 재생, 글래스모피즘 UI, 캐릭터 애니메이션 조건 분리가 적용된 상하이 72시간 게임. 시네마틱 톤의 UI와 다중 감각 피드백으로 몰입감을 제공하며, 게임 플레이 중 AI API 호출은 0회이다
Narrowing(범위 한정)S1의 씬 진행 로직, 정답/오답 판정, 목숨·힌트 시스템은 변경하지 않는다. 난이도 선택 UI만 추가하고 난이도별 데이터 분기는 이 단계에서 미구현이다. 효과음은 WebAudio API로 코드 내에서 생성하여 외부 파일 의존 없음. 게임 플레이 중 AI API 호출은 0회이다

[부록 표8-4] 상하이 72시간 2단계 프롬프트 핵심 구현 지시

구현 영역 · 핵심 지시 내용
난이도 선택UI게임 진입 시 가장 먼저 난이도 선택 화면을 표시한다. 3개 카드: ◻ 첫 상하이(beginner), ⚡ 상하이 적응중(intermediate), ◻ 상하이 마스터(advanced). selectedDifficulty 상태를 전역으로 저장하고, 선택 후 이름 입력 → 캐릭터 선택 → Day 선택으로 이동한다
선택지 셔플매 씬 진입 시 choices 배열을 Fisher-Yates 셔플로 랜덤 재배치한다. 내레이션 씬(mode: "narration")의 "继续" 버튼은 셔플하지 않는다. 렌더링 시점에 적용하고 원본 데이터는 변경하지 않는다
캐릭터 애니메이션dialogueAnimKey는 씬 변경마다 갱신하고, characterAnimKey는 characterAssetId가 변경될 때에만 갱신한다. prevCharacterAssetId를 useRef로 추적하여 같은 캐릭터가 연속 등장하면 캐릭터 이미지를 유지하고 대사만 새로 애니메이션한다
효과음7종AudioContext로 직접 생성한다. (1) 클릭: 1000Hz 50ms, (2) 힌트: 600→800Hz 150ms, (3) 정답: 800→1200Hz 200ms, (4) 오답: 300→200Hz 150ms, (5) Day 클리어: 도-미-솔 각 150ms, (6) 게임 클리어: 도-미-솔-도 각 150ms, (7) 시간 종료: 400→200Hz 300ms. ◻/◻ 토글 + localStorage 저장
TTS 음성 재생NPC 퀴즈 씬 진입 시 자동 재생(Web Speech API: utterance.lang = 'zh-CN'). 대화 패널에 ◻ 듣기 버튼 배치. 내레이션 씬(player_prompt)은 TTS 미적용. 사운드 OFF이면 자동 재생 중단
글래스모피즘UI난이도 선택·Start·Day 선택 화면에 적용. 카드: backdrop-filter: blur(12px), background: rgba(255,255,255,0.1), border-radius: 16px. Day 카드를 타임라인 연결형으로 구성하고 상태 배지(완료/진행 가능/잠김)와 보상 아이템 아이콘을 표시한다

RISEN 요소 · 상하이 72시간 S3 적용
Role(역할)S1·S2로 구현된 상하이 72시간 게임의 씬 데이터를 하드코딩에서 Supabase 런타임 로딩으로 마이그레이션하고, 7에피소드 38문항을 9에피소드 108문항으로 확장하며, 3개 난이도별 756행의 학습 문항 데이터를 구축하고, MiniMax TTS로 254개 NPC 음성을 사전 생성하고, 하드코딩 복습을 동적 수집 기반으로 개편하여 게임을 완성하는 React/TypeScript 웹앱 개발 전문가
Instructions (지시)Supabase에 sh72_scene_skeleton(108행)과 sh72_questions(756행) 2개 테이블을 생성하고 SQL로 데이터를 임포트한다. scenes.ts에서 38개 퀴즈 씬을 제거하고 내레이션 씬 7개와 EP 클리어 씬 9개만 정적으로 유지한다. DAY_CONFIG를 9에피소드 기준으로 업데이트한다. Shanghai72Page.tsx에 fetchDbScenes 함수를 구현하여 난이도 선택 시 Supabase에서 데이터를 로드하고 정적 씬과 동적 퀴즈 씬을 병합하는 하이브리드 로딩 구조를 구축한다. assets.ts에 v3 배경 별칭 22개를 추가한다. TTS 254개 mp3의 Cloudinary URL을 게임 코드에 연동한다. 하드코딩 복습 데이터를 제거하고 NPC 정답 동적 수집 기반의 학습 요약으로 개편한다
Steps(단계)① Supabase SQL Editor에서 2개 테이블 생성 및 데이터 임포트, ② scenes.ts 리팩토링(38개 퀴즈 제거, EP 클리어 9개 확장, DAY_CONFIG 업데이트), ③ Shanghai72Page.tsx에 fetchDbScenes 함수 구현(skeleton + questions → Scene 객체 → 정적 씬과 병합), ④ Supabase 자동생성 타입 미반영 대응(supabase as any 타입 우회), ⑤ assets.ts에 v3 배경 별칭 22개 추가 및 배경 7장 신규 등록, ⑥ TTS 254개 mp3 Cloudinary URL 연동, ⑦ 복습 시스템 개편(하드코딩 dayReviews 제거, LearnedSentence 동적 수집, Day Summary·Game Clear 학습 요약 교체, Start 화면 이어하기·복습 노트 버튼 배치)
End goal(최종 목표)3일 9에피소드 108문항, 3개 난이도(756행)의 상하이 여행 시뮬레이션 게임 최종 완성판. Lovable Cloud 데이터베이스 런타임 로딩으로 난이도별 데이터 분기가 실현되고, 58장 AI 이미지와 254개 TTS 음성으로 다중 감각 학습이 완성된다. 게임 중 NPC 정답을 동적으로 수집하여 Day Summary와 Game Clear에서 학습 요약을 제공하며, 게임 플레이 중 AI API 호출은 0회이다
Narrowing(범위 한정)S1·S2의 게임 흐름, 글래스모피즘 UI, 효과음, 선택지 셔플, 캐릭터 애니메이션 조건 분리는 변경하지 않는다. TTS는 NPC 대사 254개만 대상이며 플레이어 내면 독백 70개는 TTS 미적용이다. Supabase 자동생성 타입에 신규 테이블이 미반영되므로 타입 우회를 사용한다. 이어하기·복습 노트 버튼은 비활성 상태로 배치하며 Supabase 저장 연동은 이 단계에서 미구현이다. 게임 플레이 중 AI API 호출은 0회이다

[부록 표8-6] 상하이 72시간 3단계 프롬프트 핵심 구현 지시

구현 영역 · 핵심 지시 내용
SQL 테이블 생성sh72_scene_skeleton: scene_key(PK), episode, day, position, category, speaker_type, background_id, character_id, npc_name. sh72_questions: difficulty, day, episode, scene_key, prompt_chinese, prompt_pinyin, prompt_korean, choice_id, choice_chinese, choice_pinyin, choice_korean, is_correct, time_cost, next_behavior
scenes.ts 리팩토링38개 퀴즈 씬 전체를 제거한다. 타입 정의, DAY_CONFIG, 내레이션 씬 7개, EP 클리어 씬 9개(기존 6개에서 확장)를 정적으로 유지한다. DAY_CONFIG 업데이트: Day 1 clearEpClear를 ep_clear_3으로, Day 2를 ep_clear_6으로 변경한다. export를 staticScenes로 변경하고 gameScenes = staticScenes로 하위호환 alias를 유지한다
fetchDbScenes 함수(1) sh72_scene_skeleton 전체 fetch, (2) sh72_questions에서 선택 난이도 기준 fetch, (3) questions를 scene_key로 그룹핑, (4) skeleton을 episode+position 순서로 정렬, (5) 각 skeleton 행에 대해 Scene 객체 생성(정답→다음 씬, 오답→같은 씬, EP 마지막→ep_clear), (6) allScenes = { ...staticScenes, ...dbScenes }로 정적+동적 병합
TypeScript 타입 우회Supabase 자동생성 타입에 수동 추가 테이블이 미반영되므로 const db = supabase as any; db.from("sh72_scene_skeleton").select("*") 형태로 우회한다
TTS URL 전환Web Speech API fallback에서 Cloudinary mp3 URL 기반으로 전환한다. 패턴: shanghai72/audio/tts/{difficulty}/{scene_key}.mp3. NPC 씬 진입 시 자동 재생, ◻ 듣기 버튼 수동 재생. 내면 독백(player_prompt)은 TTS 미적용
복습 시스템 개편하드코딩 dayReviews를 제거하고 LearnedSentence 타입(sceneKey, episode, day, npcName, npcChinese, npcPinyin, npcKorean, answerChinese, answerPinyin, answerKorean)을 정의한다. 정답 선택 시 NPC 씬이면 질문+정답을 동적 수집한다. Day Summary와 Game Clear의 복습 아코디언을 제거하고 수집 데이터 기반 배운 문장 수 요약으로 교체한다. Start 화면에 이어하기·복습 노트 버튼을 비활성 상태로 배치하고 로그인 안내 문구를 표시한다

이 페이지는 학위논문 부록 1 가운데 4.5 여행 회화 게임: 상하이 72시간의 단계별 프롬프트 기록을 옮긴 것이다. 본문에는 이를 하나로 요약한 RISEN 통합 표만 실었다. 부록 1 전체 목록으로 돌아가기

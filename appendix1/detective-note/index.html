자료 01

[부록 표14-1] RISEN 프레임워크 기반 탐정 노트 S1 프롬프트 설계

RISEN 요소 · 탐정 노트 S1 적용
Role(역할)중국어 교육 영상 관찰 기록 게임의 DB 설계자이자 Lovable Cloud Database 운영 전문가. Supabase SQL Editor를 통한 테이블 생성, 데이터 삽입, RLS 정책 설정에 정통한 전문가
Instructions(지시)첨부된 SQL 파일을 실행하여 6개 테이블을 생성하고 게임 데이터를 삽입한다. 메인 허브의 6장 영상 기반 게임 카드 중 Game 14를 탐정 노트로 수정하고, /game/detective-note 빈 라우트를 생성한다
Steps(단계)① 첨부된 SQL 파일로 6개 테이블 생성 및 데이터 삽입(worlds 3행, episodes 3행, clips 9행, questions 22행, progress 빈 테이블, leaderboard 빈 테이블), ② RLS 정책 설정, ③ 메인 허브 Game 14 카드를 탐정 노트로 수정, ④ /game/detective-note 빈 라우트 생성
End goal(최종 목표)6개 테이블에 게임 데이터가 적재되고, 메인 허브에서 탐정 노트 카드가 활성 상태로 표시되며, /game/detective-note 라우트가 생성된 상태
Narrowing(범위 한정)① 기존 게임 코드 일체 수정 금지. ② 기존 Supabase 테이블 스키마 변경 금지. ③ 기존 Edge Function 코드 수정 금지. ④ 2~4장 허브 카드 수정 금지. ⑤ 게임 본체는 S2에서 구현
자료 02

[부록 표14-2] 탐정 노트 1단계 프롬프트 핵심 구현 지시

구현 영역 · 핵심 지시 내용
SQL 테이블 생성detective_worlds(3행), detective_episodes(3행), detective_clips(9행), detective_questions(22행), detective_progress(빈 테이블), detective_leaderboard(빈 테이블)의 6개 테이블. RLS 설정: 게임 데이터 4테이블은 전체 읽기 허용, 진행 기록과 리더보드는 본인만 읽기·쓰기
질문 데이터 구조answer_pool JSONB로 복수 정답 배열 저장(예: ["米饭", "饭"]). card_choices JSONB로 월드1 카드 4장 데이터 저장(hanzi, pinyin, emoji 포함). 월드2 이상은 card_choices NULL. hint_keyword TEXT로 병음 첫 글자 힌트 저장
영상 클립 데이터clip_order로 순서 관리. video_url에 Cloudinary MP4 URL 저장. duration(10 또는 15초)으로 동적 타임아웃 산출 기준 제공. scene_description에 수사 지시문 저장
허브 카드 수정5장 영상 기반 게임 카드 중 Game 14를 탐정 노트(侦探笔记)로 수정. 아이콘 🔍, 등급 1~9급, "플레이" 활성 상태. 클릭 시 /game/detective-note로 네비게이션

자료 03

[부록 표14-3] RISEN 프레임워크 기반 탐정 노트 S2 프롬프트 설계

RISEN 요소 · 탐정 노트 S2 적용
Role(역할)중국어 교육 영상 관찰 기록 게임 설계자이자 React 기반 웹앱 개발 전문가. AI 영상 재생, 카드 선택과 IME 한자 타이핑 이중 입력, 사전 정답 풀 매칭, 하트 기반 힌트 시스템을 구현할 수 있는 전문가
Instructions(지시)Supabase에서 6개 테이블의 데이터를 로드하여 게임을 구현한다. 영상 재생, 카드 선택과 IME 한자 타이핑의 이중 입력 방식, 사전 정답 풀 매칭, 하트 3개와 2단계 힌트 시스템, 탐정 수첩 정답 기록, 한국어 번역 토글, 탐정 등급 시스템, 에피소드별 리더보드, 진행 저장 및 복원, BGM과 효과음 7종을 포함한다
Steps(단계)① Supabase 6개 테이블에서 데이터 로드, ② 게임 시작 화면과 월드 선택 화면 구현, ③ 에피소드 선택 화면 구현, ④ 영상 재생과 자동재생 차단 대비, ⑤ 질문 표시와 카드 선택 모드 구현(월드1), ⑥ IME 한자 타이핑 모드 구현(월드2, 월드3), ⑦ 사전 정답 풀 매칭 판정, ⑧ 하트 3개와 2단계 힌트 시스템 구현, ⑨ 탐정 수첩 정답 기록 구현, ⑩ 클립 전환과 결과 요약 구현, ⑪ 에피소드 클리어 결과 모달과 탐정 등급 구현, ⑫ 에피소드별 리더보드 구현, ⑬ 진행 저장 및 복원 구현, ⑭ BGM과 효과음 7종 구현, ⑮ 모바일 반응형 최적화
End goal(최종 목표)3월드 3에피소드의 영상 관찰 기록 게임. AI 영상 재생, 카드 선택과 IME 한자 타이핑, 사전 정답 풀 매칭, 하트 기반 힌트 시스템, 탐정 수첩, 탐정 등급, 에피소드별 리더보드, 진행 저장, BGM과 효과음을 갖춘 학습형 탐정 게임
Narrowing(범위 한정)① 모든 영상은 사전 생성하여 Cloudinary URL로 제공한다. ② 게임 플레이 중 AI API 호출은 0회이다. ③ 월드1은 카드 선택, 월드2 이상은 IME 타이핑으로 input_type 컬럼에 따라 분기한다. ④ 비로그인 사용자도 플레이 가능하되 진행 저장과 리더보드 등록은 로그인 사용자에 한한다. ⑤ 기존 게임 코드는 일체 수정하지 않는다
자료 04

[부록 표14-4] 탐정 노트 2단계 프롬프트 핵심 구현 지시

구현 영역 · 핵심 지시 내용
영상 재생video 태그에 src를 직접 넣지 않고 <source> 태그로 분리한다. muted 속성 제거(Audio ON — 소리도 관찰 단서). 자동 재생 차단 대비 "▶ 영상 재생" 버튼 제공. 동적 타임아웃: clip.duration + 5초, 재생 버튼 클릭 시점부터 시작
이중 입력 방식월드1(input_type="card"): card_choices JSONB에서 4장 로드, Fisher-Yates 셔플(useMemo), 2×2 그리드. 월드2 이상(input_type="ime"): 한자 입력창(inputMode="text"), 자동 포커스, "제출" 버튼
정답 판정입력값.trim()을 answer_pool 배열과 매칭. 카드 선택: 선택한 카드의 hanzi 값으로 매칭. 복수 정답 허용(예: ["米饭", "饭"] 모두 정답)
힌트·하트에피소드당 하트 3개. [💡 영상 다시보기] 하트 1개 소모로 영상 재재생. [💡 키워드 힌트] 하트 1개 소모로 hint_keyword 표시. 하트 0개면 버튼 비활성화
탐정 수첩게임 플레이 화면 하단에 bg-amber-50 노트 영역. 정답 시 한자, 병음, 뜻이 슬라이드인 애니메이션으로 순차 기록. ANSWER_DISPLAY 매핑으로 병음과 뜻 표시
한국어 번역 토글질문의 한국어 번역은 기본 숨김. "📝 해석 보기" 토글 버튼으로 표시·숨김 전환. 하트 소모 없음. 질문마다 독립 초기화
BGM·효과음BGM: 게임 플레이 진입 시 시작, 기본 볼륨 0.3, 영상 재생 중 0.1, 질문 단계 0.3 복원, 클리어 시 fade out 정지. 효과음 7종: Web Audio API로 합성(외부 파일 불필요)
사건 파일 카드영상 아래에 bg-amber-50 border-amber-300의 수사 지시 카드 표시. 📋 아이콘 + "수사 지시" 라벨 + scene_description + "CONFIDENTIAL" 워터마크
자료에 관하여

이 페이지는 학위논문 부록 1 가운데 6.3 영상 관찰 기록 게임: 탐정 노트의 단계별 프롬프트 기록을 옮긴 것이다. 본문에는 이를 하나로 요약한 RISEN 통합 표만 실었다. 부록 1 전체 목록으로 돌아가기

핵심 구현 지시 표는 Lovable에 입력한 프롬프트 가운데 핵심 지시에 해당하는 부분을 정리한 것으로, 프롬프트 전문은 아니다. 제시한 문구는 실제 입력 기록이므로 사후에 수정하지 않았으며, 본문에서 ‘웹앱의 데이터 저장소(Lovable Cloud)’로 표기한 대상이 ‘Supabase’로 나타나는 등 본문 표기와 일치하지 않는 부분이 있다.

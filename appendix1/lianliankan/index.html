자료 01

[부록 표5-1] RISEN 프레임워크 기반 사천성 S1 프롬프트 설계

RISEN 요소 · 사천성 S1 적용
Role(역할)중국어 교육용 사천성 게임을 구현하는 React/TypeScript 웹앱 개발 전문가. Supabase 기반 데이터베이스 설계, BFS 경로 연결 알고리즘, 이모지 기반 한자 매칭 게임 인터랙션에 정통한 전문가
Instructions (지시)Supabase에 5개 테이블을 생성하고 271개 단어 CSV와 월드·스테이지 시드 데이터를 적재한다. 월드 선택, 스테이지 선택, 게임 플레이, 클리어 결과의 4화면 웹앱을 구현한다. 어휘 풀에서 무작위 추출 시 같은 이모지를 가진 단어의 동시 추출을 방지하고 1단어 4카드 원칙으로 보드를 구성한다. 너비 우선 탐색 기반 경로 연결 알고리즘으로 꺾임 2회 이내의 매칭을 판정한다. 교착 상태 감지 시 자동 셔플을 발동한다. 콤보 시스템과 별 평가, 셔플·힌트 아이템, 어휘 도감을 구현한다
Steps(단계)① Supabase에 어휘, 월드, 스테이지, 진행도, 수집 기록의 5개 테이블 생성 및 시드 데이터 적재, ② 4화면 구조 웹앱 생성(월드 선택→스테이지 선택→게임 플레이→클리어 결과), ③ 어휘 풀 무작위 추출 시 이모지 중복 필터링 및 단어당 4카드 보드 생성, ④ BFS 경로 연결 알고리즘 구현 및 교착 감지·자동 셔플 구현, ⑤ 콤보 시스템, 별 평가, 셔플·힌트 아이템, 어휘 도감 구현
End goal(최종 목표)7개 카테고리 월드에 14개 스테이지씩 총 98개 스테이지로 구성된 사천성 게임의 기본 골격. 271개 단어의 이모지를 활용하여 형태와 의미의 직접 연결을 강화하며, 풀 랜덤 추출로 무한 리플레이를 지원하는 교육용 매칭 게임
Narrowing(범위 한정)이모지는 유니코드 문자이므로 로딩 실패가 없다. 보드 크기는 모바일 화면 기준 최대 9×8이다. 경로 알고리즘은 너비 우선 탐색을 사용한다. 게임 플레이 중 API 호출은 0회이다. 기존 다른 게임 코드, Supabase 테이블 스키마, 메인 허브 코드를 일체 수정하지 않는다
자료 02

[부록 표5-2] 사천성 1단계 프롬프트 핵심 구현 지시

구현 영역 · 핵심 지시 내용
SQL 테이블 생성sichuan_vocabulary, sichuan_worlds, sichuan_stage_config, sichuan_user_progress, sichuan_vocabulary_collection의 5개 테이블 컬럼 정의. RLS 설정(어휘·월드·스테이지는 전체 읽기, 진행도·수집은 사용자별)
CSV 데이터 적재sichuan_emoji_vocabulary.csv(271행) 첨부 업로드. 컬럼: word, pinyin, meaning_kr, emoji, level, category, subcategory
시드 데이터월드 7행(id, name, icon, subcategories 배열, badge_name, pool_size), 스테이지 14행(stage_number, phase, vocab_count, card_count, grid_cols, grid_rows, match_type, time_limit)
보드 구성어휘 풀에서 N종 랜덤 추출(subcategory 기준), 같은 emoji 값 동시 추출 금지(이모지 중복 방지), 1단어 = 4카드(이모지 2장 + 텍스트 2장)
BFS 경로 연결상태: (row, col, 방향, 꺾임 횟수). 직선 최대 3개(꺾임 최대 2회). 빈 셀만 통과, 보드 바깥 1칸 가상 공간 통과 가능. 경로 존재 시 연결선 0.3초 표시 후 카드 소멸
교착 감지매 매칭 후 매칭 가능한 쌍이 0개인지 자동 검사. 0개이면 자동 셔플, 3회 시도 후 불가 시 보드 재구성
점수·별 평가기본 100점/매칭. 콤보: 2연속 ×1.2, 3연속 ×1.5, 5연속 ×2.0, 10연속+ ×3.0. 별: ⭐ 클리어, ⭐⭐ 잔여 50%+셔플 미사용, ⭐⭐⭐ 잔여 50%+힌트·셔플 모두 미사용
게임 흐름월드 선택(7개 카드) → 스테이지 선택(14개, 2열 그리드) → 게임 플레이(HUD + 보드 + 하단 버튼) → 클리어 결과(매칭 단어 목록 + 통계 + DB 저장)

RISEN 프롬프트 설계와 Lovable 입력 프롬프트의 핵심 지시

자료 03

[부록 표5-3] RISEN 프레임워크 기반 사천성 S2 프롬프트 설계

RISEN 요소 · 사천성 S2 적용
Role(역할)S1으로 구현된 사천성 게임의 매칭 체계를 단순화하고, 마작패 스타일 카드 디자인, Web Audio API 효과음, fal.ai 생성 배경 이미지, 중국어 폰트, 도감 발음 재생, 모바일 최적화를 적용하여 게임을 완성하는 React/TypeScript 웹앱 개발 전문가
Instructions(지시)S1의 매칭 유형 4종을 이모지↔한자 1종으로 통일하고 병음·뜻 카드를 제거한다. 카드를 마작패 스타일(세로 직사각형, CSS box-shadow 3D 입체감)로 전면 교체한다. Web Audio API로 효과음 8종(카드 선택음, 매칭 성공음, 매칭 실패음, 클리어 팡파레, 콤보 효과음 3종, 타이머 위기 심장박동)을 코드 내에서 직접 생성한다. fal.ai로 생성한 빨간 용 문양 배경 이미지를 적용하고 전체 오버레이로 가독성을 확보한다. 중국어 폰트 Noto Sans SC를 적용한다. 어휘 도감에 Web Speech API 발음 재생 기능을 추가한다. 타이머 위기 연출과 모바일 반응형 최적화를 적용한다
Steps(단계)① 매칭 유형을 이모지↔한자 1종으로 통일(병음·뜻 카드 제거, match_type 분기 로직 삭제), ② 마작패 스타일 카드 디자인 적용(세로 직사각형, box-shadow 3D, 아이보리 바탕), ③ Web Audio API 효과음 8종 구현(외부 파일 없이 코드 내 생성), ④ 콤보 이펙트 시각 연출 구현(텍스트 팝업, 화면 흔들림, 무지개색), ⑤ 중국어 폰트 Noto Sans SC 적용, ⑥ fal.ai 생성 빨간 용 배경 이미지 + 전체 오버레이 적용, ⑦ 어휘 도감 레이아웃 재설계 + Web Speech API TTS 발음 재생 추가, ⑧ 타이머 위기 연출(보드 테두리 깜빡임 + 심장박동 효과음) 및 모바일 반응형 최적화
End goal(최종 목표)이모지↔한자 단일 매칭, 마작패 카드 디자인, 효과음 8종, 빨간 용 배경, 중국어 폰트, 도감 TTS, 타이머 위기 연출, 모바일 최적화가 모두 적용된 사천성 최종 완성판. 7개 월드 × 14개 스테이지의 98개 스테이지에서 271개 단어의 무한 리플레이를 지원하는 교육용 매칭 게임
Narrowing(범위 한정)S1에서 구현한 BFS 경로 연결 알고리즘, 교착 감지·자동 셔플, 1단어 4카드 원칙, 콤보 배율, 별 평가 기준은 변경하지 않는다. DB 테이블 스키마를 변경하지 않는다. 기존 게임 코드·메인 허브를 수정하지 않는다. 게임 플레이 중 API 호출은 0회이다. 효과음은 Web Audio API로 코드 내에서 생성하여 외부 파일 의존이 없다
자료 04

[부록 표5-4] 사천성 2단계 프롬프트 핵심 구현 지시

구현 영역 · 핵심 지시 내용
매칭 유형 통일이모지↔한자 1종으로 통일한다. 병음·뜻 카드 관련 코드 전부 삭제한다. match_type별 분기 로직(mixed, all, img_pinyin)을 삭제한다. 점수 차등을 삭제하고 매칭 1회 = 100점으로 통일한다
마작패 카드 디자인세로 직사각형(가로:세로 = 1:1.3). box-shadow: 3px 3px 0px #B8A88A, 2px 2px 0px #C8BDA0으로 3D 입체감을 구현한다. 윗면 아이보리(#FFFFF0), border-radius: 6px. 이모지 카드는 카드 높이의 60%, 한자 카드는 남색(#1A1A2E) Noto Sans SC font-weight: 700
효과음8종AudioContext로 직접 생성한다. (1) 카드 선택: 1000Hz 50ms, (2) 매칭 성공: 800→1200Hz 200ms, (3) 매칭 실패: 300→200Hz 150ms, (4) 클리어 팡파레: 도-미-솔 각 150ms, (5) 콤보 3연속: 1200→1600Hz 150ms, (6) 콤보 5연속: 도+미 화음 200ms, (7) 콤보 10연속+: 도-미-솔 빠른 각 100ms, (8) 타이머 위기 심장박동: 80Hz "둥-둥" 1초 간격(잔여 20% 이하). 사운드 ON/OFF 토글 + localStorage 저장
빨간 용 배경bg_red_dragon.png를 게임 플레이+클리어/실패 배경으로 사용한다. background: #8B1A1Aurl(...) center/cover(fallback 색상으로 로딩 플래시 방지). 전체 오버레이: position fixed, rgba(0,0,0,0.3). 월드/스테이지 선택은 기존 밝은 배경 유지
도감 재설계+ TTS가로 레이아웃(왼쪽 이모지 48px + 오른쪽 한자/병음/뜻). Web Speech API: utterance.lang = 'zh-CN', 수집 완료 단어만 TTS 활성. 카테고리 필터 7개 월드별 탭. 수집률 "N/271개 수집" 표시
모바일 최적화보드 자동 조절(6×4 기본, 9×8은 세로 스크롤 + HUD/버튼 sticky). 하단 4버튼 1행: ◻ 나가기, ◻ 셔플, ◻ 힌트, ⏸ 일시정지. 최소 44×44px. 셔플·힌트 버튼에 잔여 횟수 빨간 원형 배지 표시
자료에 관하여

이 페이지는 학위논문 부록 1 가운데 4.2 한자 매칭 게임: 사천성의 단계별 프롬프트 기록을 옮긴 것이다. 본문에는 이를 하나로 요약한 RISEN 통합 표만 실었다. 부록 1 전체 목록으로 돌아가기

핵심 구현 지시 표는 Lovable에 입력한 프롬프트 가운데 핵심 지시에 해당하는 부분을 정리한 것으로, 프롬프트 전문은 아니다. 제시한 문구는 실제 입력 기록이므로 사후에 수정하지 않았으며, 본문에서 ‘웹앱의 데이터 저장소(Lovable Cloud)’로 표기한 대상이 ‘Supabase’로 나타나는 등 본문 표기와 일치하지 않는 부분이 있다.

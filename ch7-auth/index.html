자료 04

역할 기반 인증 체계 구현 프롬프트

Lovable 입력 내용
user_roles 테이블을 생성하고, 회원가입 시 교수자 인증 코드와 반 초대 코드를 통해 역할 부여 및 반 소속을 처리하며, AuthContext에서 역할을 전역 관리하는 기능을 구현해줘.
[1. DB — user_roles 테이블 생성]
- user_roles 테이블 생성: user_id(uuid, PK, FK→auth.users), role(app_role enum)
- app_role enum 타입: 'learner', 'instructor'
- has_role(user_id uuid, role app_role) SECURITY DEFINER 함수 생성
- RLS 활성화: 본인 역할만 SELECT 가능
- 기존 사용자 전체를 'learner'로 INSERT
[2. UI — 회원가입 화면]
- 회원가입 탭의 비밀번호 입력란 아래에 2개 입력란 추가:
(a) 교수자 인증 코드
- Label: "교수자 인증 코드 (선택)"
- placeholder: "교수자인 경우에만 입력하세요"
- 필수 아님
(b) 반 초대 코드
- Label: "반 초대 코드 (선택)"
- placeholder: "교수자에게 받은 6자리 코드"
- 필수 아님
[3. 회원가입 로직]
- 교수자 인증 코드 처리:
- 코드 미입력 → user_roles에 role='learner' 저장
- 코드 'TEACHER2026' 일치 → role='instructor' 저장
- 코드 불일치 → "인증 코드가 올바르지 않습니다. 학습자 계정으로 가입됩니다." toast + role='learner' 저장
- 반 초대 코드 처리:
- 코드 미입력 → profiles.class_id = NULL (미소속)
- 코드 입력 시 → classes 테이블에서 invite_code 일치 검색
- 일치하는 반 존재 → profiles.class_id = 해당 반 id 저장 + "반에 소속되었습니다." toast
- 일치하는 반 없음 → "유효하지 않은 반 코드입니다." toast + class_id = NULL
[4. AuthContext — role 연동]
- AuthContextType에 role: 'learner' | 'instructor' | null 추가
- onAuthStateChange에서 session 생성 시 user_roles 테이블에서 role 조회 → state 저장
- 로그아웃 시 role = null
- 게스트 모드 시 role = null
- role 조회 완료 전 loading 유지
[주의사항]
- 기존 profiles 테이블의 다른 컬럼은 변경하지 말 것 (class_id 컬럼 추가/업데이트만)
- 기존 RLS 정책은 변경하지 말 것
- AuthContext의 onAuthStateChange 콜백은 절대 async로 만들지 말 것
- 게스트 모드, 로그인 탭은 변경하지 말 것

자료 10

반 관리 및 접근 제어 구현 프롬프트

Lovable 입력 내용
교과목·반 관리 페이지를 좌우 분할 구조로 구현하고, 교수자가 교과목과 반을 생성·관리하며, 학습자가 초대 코드로 반에 소속되는 구조를 구현해줘.
[1. DB — classes 테이블 생성] CREATE TABLE classes ( id UUID DEFAULT gen_random_uuid() PRIMARY KEY, instructor_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE, name TEXT NOT NULL, invite_code TEXT NOT NULL UNIQUE, description TEXT, curriculum_id UUID REFERENCES curricula(id) ON DELETE SET NULL, created_at TIMESTAMPTZ DEFAULT NOW() );- invite_code: 6자리 영숫자 자동 생성 (generate_invite_code() DB 함수)
- curriculum_id: 연결된 교과목 (N:1, 하나의 교과목에 복수 반 연결 가능)
[2. DB — profiles 테이블에 class_id 추가] ALTER TABLE profiles ADD COLUMN class_id UUID REFERENCES classes(id) ON DELETE SET NULL; - nullable: 반 미소속 학습자는 NULL
- ON DELETE SET NULL: 반 삭제 시 미소속 복귀
[3. RLS 정책 — classes 테이블]
- SELECT: 모든 로그인 사용자 (학습자가 invite_code로 반을 찾아야 하므로)
- INSERT: instructor 역할만 (user_roles 확인)
- UPDATE: 본인이 만든 반만 (instructor_id = auth.uid())
- DELETE: 본인이 만든 반만 (instructor_id = auth.uid())
[4. 교과목·반 관리 페이지 (/admin/classes) — 좌우 분할] 좌측 패널 — 교과목 목록: - 상단: [+ 새 교과목 만들기] 버튼
- 교과목 카드 목록: 교과목명 + 연결된 반 수 (예: "반 2개 (초급 A반, 초급 B반)")
- 카드 클릭 시 우측에 상세 표시 우측 패널 — 교과목 상세 + 반 목록: - 교과목 상세: 교과목명, 설명, 연결된 반 수 배지, 생성일
- 버튼 3개: [ 커리큘럼 편집] → /admin/curriculum/:id 이동, [ 복제], [ 삭제]
- 반 목록 구분선
- 각 반 카드:
- 반 이름, 설명
-  소속 교과목: 드롭다운 (교수자의 모든 교과목 목록, 변경 시 curriculum_id UPDATE)
-  초대 코드: 6자리 코드 + [복사] 버튼
-  소속 학습자: N명
- [✏ 수정] [ 반 삭제] 버튼
- ▶ 학습자 보기 / ▼ 학습자 숨기기 토글
- 펼침 시: 소속 학습자 목록 (닉네임 + 아바타) + 각 학습자 옆 [제외] 버튼
- [제외] 클릭 시: 확인 후 해당 학습자의 profiles.class_id = NULL
- 반 목록 하단: [+ 반 추가] 버튼 (선택된 교과목에 반 추가)
[5. 학습자 커리큘럼 조회 경로]
- profiles.class_id → classes.curriculum_id → curricula
- 학습 코치 허브에서 이 경로로 현재 커리큘럼을 조회하여 오늘의 학습에 반영
[6. 교수자 데이터 격리]
- 교수자가 학습 현황, 성적표 등을 조회할 때 자신의 반에 소속된 학습자만 조회
- SECURITY DEFINER 함수로 접근 범위 제한
[주의사항]
- 기존 profiles 테이블의 다른 컬럼, RLS 정책은 변경하지 말 것 (class_id 추가만)
- 기존 curricula 테이블은 변경하지 말 것
- 기존 게임 코드, AuthContext는 변경하지 말 것
- AuthContext의 onAuthStateChange 콜백은 절대 async로 만들지 말 것
자료에 관하여

이 페이지는 학위논문 제7장 7.2.1에서 다룬 웹앱 설계 및 활용 기능의 개발 기록 가운데, 지면에서 생략한 프롬프트 입력 기록과 개발 과정의 주요 화면을 수록한 것이다. 화면은 개발 당시의 기록이므로 현재의 웹앱과 다를 수 있다.

수록한 프롬프트는 실제 입력 기록이므로 문구를 사후에 고치지 않았다. 다만 인쇄 지면에 맞추어 줄이 나뉜 부분은 화면에서 읽기 쉽도록 다시 이어 붙였다.

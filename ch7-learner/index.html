자료 05

학습 코치 및 AI 멘토 구현 프롬프트

Lovable 입력 내용
학습자의 학습 코치 허브를 구현하고, 규칙 기반 멘토와 AI 멘토를 통합해줘.
[1. 나의 학습 페이지 (/coach) — 전체 구조] 상단 고정 (탭 밖): - 프로필 바: 아바타 + 닉네임 · 칭호
- 지표 카드 4개:  플레이 게임(N/16) | ⭐ 총 별 | ✅ 수집 어휘(N개) |  총점
- 모바일 2×2 / PC 1×4 2개 탭:  오늘의 학습 (기본) |  학습 현황
[2. 오늘의 학습 탭 — PC 2열 구조] 좌측 — 학습 계획: - 교과목명 + 학기 정보 (예: " 초급중국어회화 · 2026-1학기 전공필수") - 15주 아코디언:
- 각 주차: 아이콘(완료 초록/진행 노랑/미래 회색) + "N주차: 제N과: 제목" + 날짜
- 현재 주차: 펼침 상태 + 설명 표시 +  강조
- 초기 5주 표시 + "나머지 10주차 더 보기" 버튼
- 학습자 커리큘럼 조회 경로: profiles.class_id → classes.curriculum_id → curricula 우측 — 학습 과정 + 멘토: - 상단: [ N주차 강의 노트 보기] 버튼 (lecture_notes 테이블에 해당 주차 데이터 있을 때만 표시)
- 학습 과정 카드:
- 주차 제목 (빨간색 강조)
- 학습 내용 설명
- 배정 게임 칩 (게임명 + 완료 체크 ✅, 클릭 시 해당 게임 시작 화면으로 이동)
- "→ 이번 주 게임에 도전해 보세요!" 안내
- 학습 멘토 (규칙 기반, [3] 참조)
- AI 멘토 (Claude API, [4] 참조)
[3. 규칙 기반 학습 멘토]
- 학습 데이터 분석 → 조건 충족 시 메시지 표시 (최대 5개)
- 규칙 5개:
1. 미플레이 안내: 현재 주차 배정 게임 중 미완료 존재 → "이번 주 배정 게임 N종 중 M종이 아직 남았습니다."
2. 미경험 영역: 특정 미디어 유형 미플레이 → "텍스트 영역을 아직 경험하지 않았습니다. {게임명}부터 시작해 보세요!"
3. 복습 추천: 높은 별 획득 게임 → "{게임명}에 다시 도전해 보세요! 더 높은 별을 획득할 수 있습니다."
4. 연속 학습: N일 연속 → " N일 연속 학습 중!"
5. 주차 완료: 현재 주차 전체 완료 → "이번 주 학습을 모두 완료했습니다!"
- 게임명에 하이퍼링크 (클릭 → 해당 게임 시작 화면)
- 조건 미충족 규칙은 표시 안 함
[4. AI 학습 멘토]
- 선택형 4버튼:
-  나에게 맞는 게임을 추천해 주세요
-  내 강점과 약점을 분석해 주세요
-  이번 주 학습 전략을 세워주세요
-  영역별 학습법을 알려주세요
- 클릭 시 Claude API 단발 1회 호출:
- 시스템 프롬프트: 중국어 학습 멘토 역할 + 한국어 응답
- 사용자 프롬프트: 학습자의 게임별 점수/클리어/정답률/오답/플레이 빈도/커리큘럼 진도 동적 삽입
- 커리큘럼 연동: 반 소속 시 현재 주차 정보 포함
- 응답 표시: 구조화된 텍스트 (강점/약점/제안, 게임명 볼드)
- 로딩: "AI가 학습 데이터를 분석하고 있습니다..."
- 하단: [다른 질문하기] 버튼 → 4가지 버튼 재표시
[5. 반 미가입 학습자 처리]
- 커리큘럼 영역 대신 안내 카드:
- " 반에 가입하면 수업 커리큘럼이 표시됩니다"
- "교수자에게 받은 초대 코드를 설정에서 입력하세요."
- [설정으로 이동] 버튼
- 학습 멘토 + AI 멘토는 정상 표시 (커리큘럼 없이도 게임 데이터 기반 작동)
[6. 강의 노트 열람 모달]
- [ 강의 노트 보기] 클릭 시 모달 표시
- lecture_notes 테이블에서 해당 커리큘럼 + 주차의 content_json 로드
- LectureNoteRenderer 컴포넌트로 렌더링 (교수자 편집 화면과 동일) - 6개 섹션: 주차 제목+한글 해석 / 학습목표 3개 / 핵심 단어(표+) / 핵심 문장 또는 회화() / 어법 포인트(highlight+예문+) / 배정 게임 카드
-  Web Speech API 기반 중국어 TTS
- 하단: [ 인쇄] (window.print) + [✕ 닫기]
- 강의 노트 미생성 주차: 버튼 미표시
[주의사항]
- 기존 게임 코드, AuthContext는 변경하지 말 것
- AuthContext의 onAuthStateChange 콜백은 절대 async로 만들지 말 것
- 기존 RLS 정책은 변경하지 말 것
- 학습자 커리큘럼 조회 경로: profiles.class_id → classes.curriculum_id → curricula
- Claude API: 기존 프로젝트 API 키 사용
- 대화형 채팅 아님 — 단발 1회 호출 (질문 선택 → 응답 → 다른 질문하기)
활동

게임 활동과 학습 현황

게임 허브, 학습 현황, 리더보드, 의견 보내기

게임 허브에서 16종 게임을 탐색하고, 학습 현황과 리더보드를 확인하며, 교수자에게 의견을 보낼 수 있다.

자료 06

게임 활동 및 학습 현황 구현 프롬프트

Lovable 입력 내용
학습자의 게임 탐색, 학습 현황 확인, 리더보드, 의견 보내기 기능을 구현해줘.
[1. 게임 플레이 페이지 (/games)]
- 상단: 언어 기능별 필터 탭 6개
- [전체] [ 듣기] [ 말하기] [ 읽기] [✏ 쓰기] [⭐ 내 콘텐츠]
- 듣기/말하기/읽기/쓰기는 《等级标准》 听说读写 4기능 기반
- 내 콘텐츠: 학습자 개인 단어장/문장 모음 보유 게임만 필터
- 16종 게임 카드 4열 그리드:
- 각 카드: 아이콘 + 한국어명 + 중국어명 + 설명 + 학습 기능 태그(색상 배지) + 급수 태그
- 배경색: 텍스트(초록) / 이미지(분홍) / 음성(민트) / 영상(보라)
- 클릭 시 해당 게임 시작 화면으로 이동
- 모바일: 2열 또는 1열 반응형
[2. 학습 현황 탭 (/coach 학습 현황 탭)]
- 오늘의 학습 탭과 같은 /coach 페이지의 2번째 탭
(a) 커리큘럼 진도: - " 커리큘럼 진도 (N/15주 완료)" 타이틀
- 1~15주 원형 버튼 가로 나열
- 색상: 완료(초록) / 진행중(노랑) / 미완료(빨강) / 미래(회색)
- 현재 주차: 크기 확대 + 강조
- 범례: ● 완료 ● 진행중 ● 미완료 ▒ 미래
(b) 미디어별 게임 완료도 + 주간 학습 활동 (2열): - 좌측: 도넛 4개 (文 텍스트 / 画 이미지 / 声 음성 / 影 영상)
- 각 도넛: 원형 진행률 + 중앙 퍼센트 수치 + 하단 미디어 유형명
- 가중 완료율 계산 (7.3.3.1과 동일 로직)
- 우측: 주간 학습 활동 막대 차트
- 최근 7일 요일별 플레이 횟수 (Recharts 막대)
- X축: 월~일 / Y축: 횟수
(c) 최근 게임 활동 + 교수자 피드백 (2열): - 좌측: 최근 게임 활동
- 게임명 + 미디어 유형 색상 점 + 점수 + 날짜
- 기본 5건 표시 + [더 보기 (10개)] 버튼
- 우측: 교수자 피드백
- 교수자가 전달한 피드백이 있을 때만 표시
- 생성 날짜 + "최신 피드백" 배지
- 루브릭 평가 요약 표 (항목/영역/점수/등급/기준 ⓘ)
- 서술형 피드백 7개 섹션 (학습 성취/개선/진단/미디어/빈도/커리큘럼/제안)
- 학습 체크리스트 (목표 체크 + 게임 이동 링크)
- 미전달 시: 영역 미표시
[3. 랭킹 페이지 (/ranking)]
- 5탭: [종합] [텍스트 게임] [이미지 게임] [음성 게임] [영상 게임]
- 종합: 전체 게임 총점 기준
- 미디어별: 해당 미디어 유형 게임 합산 점수
- 내 순위: 상단 고정 (아바타 + 닉네임 + "(나)" 표시 + 점수, 강조 배경)
- 종합 랭킹 TOP 20:
- 순위 + 아바타 + 닉네임 + 점수
- 1~3위:  메달 아이콘
- 내 행: 배경색 구분
- [▼ 더 보기] 버튼
- 응원 한마디:
- 메시지 입력란 + 글자 수 제한 + [전송] 버튼
- 메시지 목록: 아바타 + 닉네임 + 작성 일시 + 메시지 + ♡ 좋아요
- 페이지네이션
[4. 의견 보내기 페이지]
- 상단 안내: " 교수자에게 버그 신고, 기능 요청, 기타 의견을 보낼 수 있습니다."
- 의견 보내기 카드:
- 카테고리 3택: [ 버그 신고] [ 기능 요청] [ 기타 의견]
- 텍스트 입력란 (글자 수 표시 0/500)
- [전송] 버튼 (카테고리 미선택 또는 빈 내용 시 비활성)
- 내가 보낸 의견:
- 카테고리 배지 + 작성 일시 + 내용
- 각 항목에 [] 삭제 버튼
- 전송 시 교수자 메인 허브에  알림
[주의사항]
- 기존 게임 코드, AuthContext는 변경하지 말 것
- AuthContext의 onAuthStateChange 콜백은 절대 async로 만들지 말 것
- 기존 RLS 정책은 변경하지 말 것
- 도넛 가중 완료도 계산 로직 변경 금지
- 교수자 피드백 데이터: learner_feedback 테이블에서 조회

자료 07

개인 학습 콘텐츠 활용 구현 프롬프트

Lovable 입력 내용
학습자가 개인 단어장과 문장 모음을 관리하고, 게임에서 콘텐츠 소스를 선택하여 맞춤 플레이하는 기능을 구현해줘.
[1. 내 콘텐츠 페이지 (/my-content)] 상단 안내: " 이번 학기 학습 내용을 확인하고, 나만의 단어장과 문장을 만들어 게임에서 복습하세요."
(a) 이번 학기 학습 내용: - 교과목명 + 학기 정보 (예: " 초급중국어회화 · 2026-1학기 전공필수")
- 주차 탭 가로 나열 (현재 주차 ★ 강조)
- 주차 선택 시:
-  N주차 단어 (N개): 한자 + 병음 + 뜻 + [+ 추가] 버튼
-  N주차 문장 (N개): 문장 + 병음 + 뜻 + [+ 추가] 버튼
- [+ 추가] 클릭 시 해당 항목을 내 단어장/내 문장 모음에 INSERT
- 상단: [전체 추가] 버튼 + 표시 건수 (5개씩)
- 페이지네이션
- 반 미소속 시: "반에 가입하면 학습 내용이 표시됩니다" 안내
(b) 내 단어장: - " 내 단어장 (N개)" 타이틀 + [+ 새 단어장] 버튼
- 단어 목록: 한자 + 병음 + 뜻 + 주차 배지 (예: " 2주 차") + [] 삭제
- 표시 건수 (5개씩) + 페이지네이션
- [+ 새 단어장] 클릭 시: 한자·병음·뜻 수동 입력 모달
- 데이터: learner_custom_words 테이블
(c) 내 문장 모음: - " 내 문장 모음 (N개)" 타이틀 + [+ 새 문장 모음] 버튼
- 문장 목록: 문장 + 병음 + 뜻 + 주차 배지 + [] 삭제
- 표시 건수 (5개씩) + 페이지네이션
- [+ 새 문장 모음] 클릭 시: 문장·병음·뜻 수동 입력 모달
- 데이터: learner_custom_sentences 테이블
[2. 콘텐츠 소스 선택 UI — 커스터마이징 가능 8종 게임 시작 화면] 라디오 박스 3택: - ◉ 기본 콘텐츠로 플레이: "원본 단어/문장 데이터 사용" (biaozhun_cihui 등) - ○ 커리큘럼으로 플레이: "{교과목명} · 주차별 단어/문장으로 플레이" (curriculum_words / curriculum_sentences) - ○ 내 단어장(또는 내 문장 모음)으로 플레이: "내 단어장/문장 모음 전체 N개로 게임합니다."
(learner_custom_words / learner_custom_sentences) 대상 게임: - 내 단어장 6종: 사천성, 타자 히어로, 단어 팡팡, 한자 연금술, 성조 클라임, 분류 달인 → "내 단어장으로 플레이"
- 내 문장 모음 2종: 징검다리 점프, 버블버블 → "내 문장 모음으로 플레이" 라디오 선택에 따라 게임 데이터 소스 분기: - 기본: 기존 게임 데이터 로직 그대로
- 커리큘럼: curriculum_words / curriculum_sentences에서 로드
- 내 단어장/문장: learner_custom_words / learner_custom_sentences에서 로드
[3. 교차 활용 데이터 흐름]
- 게임 플레이 중 수집 어휘 → learner_custom_words에 INSERT (게임별 수집 로직)
- 오답 어휘 → 내 단어장에 추가 가능
- 커리큘럼 학습 내용 [+ 추가] → learner_custom_words / learner_custom_sentences에 INSERT
- 저장된 개인 콘텐츠 → 8종 게임의 "내 단어장/문장 모음으로 플레이"에서 활용
- 하나의 learner_custom_words 테이블에 모든 소스(수집/오답/수동/커리큘럼)의 단어가 통합 저장
[주의사항]
- 기존 게임 코드, AuthContext는 변경하지 말 것
- AuthContext의 onAuthStateChange 콜백은 절대 async로 만들지 말 것
- 기존 RLS 정책은 변경하지 말 것
- learner_custom_words, learner_custom_sentences 테이블의 기존 구조 변경 금지
- 콘텐츠 소스 선택 시 기존 게임 로직은 변경하지 않고 데이터 소스만 분기
자료에 관하여

이 페이지는 학위논문 제7장 7.4에서 다룬 학습자 활동 환경 기능의 개발 기록 가운데, 지면에서 생략한 프롬프트 입력 기록과 개발 과정의 주요 화면을 수록한 것이다. 화면은 개발 당시의 기록이므로 현재의 웹앱과 다를 수 있다.

수록한 프롬프트는 실제 입력 기록이므로 문구를 사후에 고치지 않았다. 다만 인쇄 지면에 맞추어 줄이 나뉜 부분은 화면에서 읽기 쉽도록 다시 이어 붙였다.
